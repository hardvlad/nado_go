# nado — план запуска на рынке Казахстана

Документ владельца продукта. Что нужно, чтобы включить платящих продавцов в КЗ:
приём денег покупателями в магазинах, оплата подписки платформе, и витрина,
которую не стыдно показать покупателю. Ниже — решения (в т.ч. ответы на открытые
вопросы), полный список задач и статус.

Легенда статуса: ✅ сделано в этой итерации · 🟡 частично/каркас · ⬜ дальше.

---

## 1. Продуктовые решения для запуска (ответы на открытые вопросы)

Приняты, чтобы не блокировать запуск. Каждое можно пересмотреть отдельной задачей.

| Тема | Решение для запуска | Почему |
|---|---|---|
| Приём денег покупателем | **BYO-мерчант продавца** (D-01), агрегатор **Freedom Pay** первым, затем **Halyk ePay**, плюс **Kaspi Pay в полуручном режиме** | Freedom Pay даёт карты + Apple/Google Pay + рассрочку одним подключением и популярен у МСБ КЗ; платформа денег не касается |
| Подписка платформе | Продавец платит **nado** картой через наш мерчант-аккаунт (тот же слой оплат, `purpose=subscription`); запасной путь — счёт на юрлицо | Автосписание карты сложнее и добавляется позже; разовая оплата периода закрывает MVP |
| Валюта | **Только KZT** на витрине и в подписке | Первый рынок — КЗ (D-13); мультивалюта отложена |
| Канал OTP | **WhatsApp** (пул GreenAPI уже есть), Telegram — позже | Инфраструктура готова (D-17) |
| Фискализация (чеки) | **Fast-follow после запуска**: Webkassa (D-08). На старте — предупреждение продавцу в кабинете | Юридически нужно, но не блокирует первую продажу; многие МСБ уже с кассой |
| Доставка | **Ручные способы** на старте (продавец задаёт варианты и цены), курьерские API позже | D-09; закрывает MVP |
| Модель дохода | **Подписка по тарифам**, без комиссии с продаж (D-06) | Продающий оффер против маркетплейсов |
| Пробный период | 14 дней на магазин, затем блок витрины до оплаты подписки | Уже есть trial (D-32), добавляется гейт по подписке |

## 2. Слой оплат (платформа + магазины)

Единый пакет `internal/integration/payment` за интерфейсом `Provider` (как маркетплейсы).
Одна таблица `payments` обслуживает и заказы витрины, и подписку (`purpose`).

- [✅] Интерфейс `Provider` (Start → ссылка на оплату; ParseCallback → результат вебхука), реестр провайдеров, подпись/проверка.
- [✅] Провайдер **dev** — детерминированный, работает офлайн: локальный e2e-сценарий и тесты без внешних вызовов.
- [✅] Провайдер **Freedom Pay** (init платежа + подпись MD5 по алгоритму PayBox, разбор result-вебхука с проверкой подписи).
- [✅] Провайдер **Kaspi (manual)** — полуручной: покупателю показываются реквизиты/QR, подтверждение оплаты — вручную продавцом (каркас статуса).
- [✅] Провайдер **Halyk ePay** (OAuth client_credentials + клиентский виджет `halyk.pay`, postLink-вебхук; по референсу EPay.php). Выбирается и на витрине, и для подписки платформы. Виджет рендерится на странице с ослабленной CSP (домены ePay), без inline-скриптов.
- [⬜] Freedom Pay refund/rebill, автосписание подписки, доп. проверка статуса ePay через check-status API.
- [✅] Таблица `payments` (миграция 0016): сумма, валюта, статус (`pending|succeeded|failed|canceled`), провайдер, внешний id, токен вебхука (хеш), `purpose`, связь с заказом/аккаунтом.
- [✅] Секреты мерчанта — в `provider_credentials` (AES-256-GCM), расшифровка только перед вызовом провайдера; в логах — `***`.
- [✅] Вебхук `/webhooks/payment/{provider}/{token}` — вне CSRF, аутентификация по токену в пути + подпись провайдера; идемпотентная обработка.

## 3. Оплаты в магазинах продавцов (deньги покупателя → продавцу)

- [✅] Настройки оплаты магазина в кабинете: выбор провайдера + реквизиты, вкл/выкл.
- [✅] Checkout → создание платежа → редирект на провайдера (или на страницу оплаты).
- [✅] Возврат с провайдера + вебхук → заказ переходит `awaiting_payment → paid`.
- [✅] Страница заказа показывает статус оплаты и кнопку «Оплатить», если не оплачен.
- [🟡] Kaspi-режим: заказ помечается «ожидает подтверждения», продавец подтверждает в кабинете (кнопка подтверждения — fast-follow).
- [⬜] Возвраты (refund) из кабинета, частичные оплаты.

## 4. Оплата подписки платформе (деньги продавца → nado)

- [✅] Страница биллинга в кабинете: текущий статус подписки, выбор тарифа, оплата.
- [✅] Оплата периода через слой оплат (`purpose=subscription`) → активация подписки на аккаунте (`subscription_status`, `subscription_until`).
- [✅] Гейтинг: по истечении пробного периода и без активной подписки витрина отдаёт «магазин временно недоступен» (мягкий гейт, настраивается).
- [⬜] Автопродление, проформы/счета для юрлиц, промокоды.

## 5. Витрина: UX/UI

- [✅] Переработка базовой темы: современный чистый вид, mobile-first, аккуратная типографика и сетка, состояния (пусто/ошибка/загрузка).
- [✅] Светлая/тёмная тема на семантических токенах (D-21), контраст AA.
- [✅] Карточка товара, листинг категории, корзина, checkout, страница заказа — приведены к единому визуальному языку.
- [✅] Шапка с поиском и корзиной, футер, «хлебные крошки».
- [⬜] Вторая тема, конфигуратор цвета бренда в кабинете, гибридные приложения.

## 6. Прочее к запуску (fast-follow)

- [⬜] Webkassa (чеки) — юридически обязательно, первый пункт после запуска.
- [⬜] Доставка: ручные способы в кабинете (СДЭК/Казпочта/Exline позже).
- [⬜] Свои домены + автоматический TLS (D-04).
- [⬜] Юридические страницы: оферта, политика конфиденциальности, возвраты.
- [⬜] Аналитика/мониторинг платежей, алерты на упавшие вебхуки.
- [⬜] Раннер миграций с таблицей `schema_migrations` (сейчас применяются вручную).

## 7. Порядок включения на проде

1. Применить миграции по `0016` включительно.
2. Задать `SECRETS_KEY`, `PLATFORM_*`, `APP_PUBLIC_URL`.
3. Завести мерчант-аккаунт платформы (Freedom Pay) и задать его креды для подписки
   (`PLATFORM_PAY_*`).
4. Продавцы подключают свой мерчант в кабинете (Настройки оплаты магазина).
5. Прописать URL вебхука `https://<домен>/webhooks/payment/freedompay/<token>` в
   кабинете провайдера (токен генерится на подключение).
6. Проверить сквозной сценарий на dev-провайдере, затем на песочнице Freedom Pay.

Эта итерация закрывает разделы 2–5 (каркас + рабочий сквозной путь на dev-провайдере
и корректные форматы Freedom Pay). Разделы 6 и отмеченное ⬜ — следующими задачами.
