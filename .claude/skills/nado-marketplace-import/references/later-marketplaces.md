# Маркетплейсы следующего этапа: Halyk Market, Мегамаркет, Avito

В MVP их нет. Причины — ниже по каждой площадке. Этот файл нужен, когда пользователь попросит
добавить одну из них: он показывает, что даёт API и где ждать проблем. Данные на сентябрь 2026 года.

## Halyk Market (Казахстан, №3 в РК: около $237 млн в 2025 году, [Forbes KZ](https://forbes.kz/ranking/object/1098))

**Почему позже:** API отдаёт мало контента. Импорт даст только скелет товара, как файл Kaspi, а
делать второй «бедный» источник до основных смысла нет.

- **Авторизация:** OAuth2 `client_credentials`, токен живёт 4 часа
  ([док](https://halyk-market.gitbook.io/anyqtama/zagruzka-tovarov-po-api/zagruzka-tovarov-bez-prais-lista-po-api/avtorizaciya.md)).
  `client_id` и `client_secret` продавец получает у Halyk Market. ⚠️ не проверено, как именно.
- **Список товаров:** `GET https://halykmarket.kz/gw/merchant/public/merchant/product`, пагинация `page`/`size`
  ([док](https://halyk-market.gitbook.io/anyqtama/zagruzka-tovarov-po-api/upravlenie-tovarami-po-api/poluchenie-spiska-tovarov.md)).
  - Отдаёт `name`, `merchantSkuCode`, `price`, общий остаток и **одно** `imageUrl`.
  - Описаний, характеристик и вариантов нет.
- **Остальное:** есть методы изменения цены и остатков, заказов и XML-прайса.
- **Маппинг:** `merchantSkuCode` → `ExternalID`, `VendorCode`, `SKU`; `name` → `Title`; `imageUrl` → `Images[0]`;
  `price` → `Price` (KZT); остаток → `StockLevel` одного условного склада.
- При реализации уточните, отдаёт ли API бренд и категорию. ⚠️ не проверено.

## Мегамаркет (РФ)

**Почему позже:** в 2025 году площадка опустилась в рейтинге Data Insight с 4-го на 38-е место
([retail.ru](https://www.retail.ru/news/wildberries-ozon-i-yandeks-market-ostalis-liderami-reytinga-data-insight-8-iyunya-2026-278630/)).
Метода чтения каталога, судя по всему, нет.

- **Документация:** <https://partner-wiki.megamarket.ru/merchant-api>. Загрузить её не удалось, ⚠️ всё ниже не проверено.
- **Что есть:** по словам интеграторов, API покрывает заказы, цены и остатки.
- **Как грузится каталог:** через YML-фид продавца, карточки — через Excel.
- **Возможный путь импорта:** если у продавца есть YML-фид (стандарт Яндекс.Маркета: `<offer id>`, `<name>`,
  `<price>`, `<picture>`, `<param>`, `<barcode>`), читать фид по URL. Это даст полный контент без API.
  Такой коннектор «YML-фид» можно сделать универсальным: его используют многие CMS и площадки.

## Avito (РФ; около 1,2 млн зарегистрированных МСП, [Коммерсантъ](https://www.kommersant.ru/doc/8847719))

**Почему позже:** это площадка объявлений, а не каталог товаров с вариантами и остатками.
API ориентирован на объявления и статистику.

- **Авторизация:** `https://api.avito.ru`, OAuth2 `client_credentials`. Ключи продавец берёт в ЛК: «Настройки → API».
  Для приложений есть и authorization code. ⚠️ не проверено, какие scopes нужны.
- **Объявления:** `GET /core/v1/accounts/{user_id}/items/{id}` отдаёт статус, услуги и статистику.
  Полного описания и фото в ответе, похоже, нет. ⚠️ не проверено.
- **Каталог продавца** живёт в «Автозагрузке» (XML-фид Avito). Импорт в nado, скорее всего, пойдёт через этот фид по URL.

## Общий вывод для реализации

Все три площадки упираются в фиды (YML или XML) и в скудное API. Когда до них дойдёт очередь, сначала
сделайте универсальный **файловый/фидовый коннектор**: Excel, YML, XML с маппингом колонок. Kaspi (путь 1),
Мегамаркет и Avito лягут на него почти без отдельного кода.
