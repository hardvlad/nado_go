# Платформа nado

## Суть продукта

Продавцы уже торгуют на маркетплейсах и платят им комиссию 15–40%. nado даёт им
собственный интернет-магазин и мобильное приложение за несколько минут.

**Регион.** Платформа зарегистрирована в Казахстане, сервер тоже в Казахстане.
Сначала работаем с продавцами КЗ, выход в РФ — отдельным этапом (D-13).

1. **Импорт.** Продавец подключает кабинеты маркетплейсов, и товары с фото,
   описаниями, характеристиками, вариантами, ценами и остатками попадают в единый
   каталог. Kaspi подключается через служебного сотрудника в кабинете продавца
   (D-19).
2. **Автообновление.** Цены и остатки периодически подтягиваются **из**
   маркетплейсов. Синхронизация односторонняя: продажа в магазине не меняет
   остатки на маркетплейсе.
3. **Цены.** Цена в магазине считается правилом от цены маркетплейса (например,
   −X% с округлением до 10 вниз) или задаётся продавцом вручную (D-14).
4. **Магазин.** Витрина на `<slug>.nado.kz` или на своём домене продавца.
   Несколько адаптивных тем, готовых к гибридным приложениям для App Store и
   Google Play (D-16). Языки RU, KK, EN, мультивалютная витрина.
5. **Покупатели.** Регистрация обязательна: вход по номеру телефона, код приходит
   через WhatsApp или Telegram (D-17).
6. **Оплата напрямую продавцу.** Продавец подключает **свой** мерчант-аккаунт.
   В КЗ это Halyk ePay, Freedom Pay и Kaspi Pay (полуручной режим), в РФ позже —
   ЮKassa и Т-Касса. Платформа деньги не принимает.
7. **Чеки.** Облачная касса продавца: Webkassa в КЗ, в РФ позже АТОЛ Онлайн.
8. **Доставка.** Ручные способы; в КЗ — СДЭК, Казпочта, Exline; в РФ позже —
   Яндекс Доставка и Почта России. В будущем возможна своя служба доставки.
9. **Монетизация.** Подписка по тарифам, без процента с продаж.

## Архитектура одним взглядом

```
                   ┌──────────── один Go-бинарник (cmd/nado) ─────────────┐
 app.nado.kz    ─► │ кабинет продавца (Go-шаблоны + htmx)                 │
 *.nado.kz      ─► │ витрины магазинов (выбор магазина по Host, темы)     │──► MS SQL Server
 свой домен     ─► │ /api/v1 (JSON)   /webhooks/{provider}/{token}        │
 приложения     ─► │ (нативная оболочка Capacitor + страницы витрины)     │──► медиа-хранилище
                   │ воркеры фоновых задач (очередь в MSSQL)              │
                   └──────────────────────────────────────────────────────┘
                          │ integration/marketplace  (Kaspi, WB, Ozon, YM)
                          │ integration/payment      (Halyk, Freedom, Kaspi | ЮKassa, Т-Касса)
                          │ integration/fiscal       (Webkassa | АТОЛ Онлайн)
                          │ integration/delivery     (СДЭК, Казпочта, Exline | Яндекс, Почта РФ)
                          └ integration/messaging    (WhatsApp Cloud API, Telegram Gateway — коды OTP)
```

Интеграции — адаптеры за интерфейсами. Бизнес-логика в `service` не знает, с каким
маркетплейсом, банком или службой доставки работает. Новый провайдер — это новый
пакет и регистрация в реестре.

## Раскладка пакетов

Скелет разложен по слоям (`repository → service → handler`). Эта схема
сохраняется, а интеграции живут отдельно:

```
internal/
  model/            доменные сущности (Account, Store, Product, Variant, Customer, Order...)
  repository/       SQL — только здесь; каждый метод принимает accountID
  service/          бизнес-правила; транзакции; постановка фоновых задач; pricing
  handler/api/      JSON API
  handler/web/      кабинет продавца (app.nado.kz)
  handler/shop/     витрина магазина (выбор по Host)
  handler/webhook/  входящие вебхуки провайдеров
  tenant/  money/  secrets/  jobs/  media/  i18n/  otp/
  integration/
    marketplace/{kaspi,wildberries,ozon,yandexmarket}/   kaspi/cabinet — вход через сотрудника
    payment/{halykepay,freedompay,kaspimanual,yookassa,tkassa}/
    fiscal/{webkassa,atol}/
    delivery/{manual,cdek,kazpost,exline,yandexdelivery,russianpost}/
    messaging/{whatsapp,telegramgateway}/
    mailbox/        IMAP: письма Kaspi служебным сотрудникам (пароль, коды MFA)
web/themes/<код темы>/  шаблоны и статика тем витрины
```

Оформление любых страниц (светлая и тёмная тема, токены, контраст) — в скилле
**nado-ui-design**. Соглашения по коду (SQL, миграции, ошибки, тесты, очередь, HTTP-клиенты) —
в скилле **nado-go-conventions**. Прочитай его перед написанием кода.

| Оформление | Светлый и тёмный вариант обязательны для всех страниц, режим «как в системе», токены, AA-контраст (D-21) |
| Покупатели | Обязательная регистрация по телефону, OTP через WhatsApp/Telegram (D-17) |

## Модель данных

Сущности и связи: `references/domain-model.md`. Главное:

- **Account** — арендатор: продавец, ИП или компания. Владеет подпиской,
  участниками, подключениями к маркетплейсам и **единым каталогом**.
- **Store** — магазин аккаунта: домены, тема, языки, валюты, правила цен, способы
  оплаты и доставки, покупатели, заказы.
- **Product → Variant.** **SKU, остатки и цены маркетплейсов относятся к
  варианту.**
- **ProductSource** связывает товар с карточкой на маркетплейсе. Карточки WB,
  Ozon и Kaspi одного товара склеиваются по штрихкоду.
- **StoreOffer** — итоговая цена варианта в магазине (правило или ручная) и его
  видимость.
- **Customer** — покупатель магазина с подтверждённым телефоном.
- **Order** хранит снимок цен и курса на момент оформления.

## Дорожная карта MVP (КЗ)

Порядок подобран так, чтобы как можно раньше получить сквозной сценарий
«импортировал → увидел магазин → оплатил» для продавца из КЗ.

1. **Фундамент:** аккаунты, участники и роли, вход в кабинет (сессии, CSRF),
   `tenant`, `money`, `secrets`, `jobs`, `media`, `i18n`, миграции.
2. **Каталог:** товары, варианты, медиа, категории, ручное редактирование, защита
   правок продавца.
3. **Импорт:** Kaspi (кабинет, запасной путь — файл), затем Wildberries и Ozon,
   затем Яндекс Маркет.
4. **Цены:** цены маркетплейсов по источникам, правила магазина, ручная цена.
5. **Витрина:** поддомены, первая тема (mobile-first), каталог, карточка, корзина,
   SEO.
6. **Покупатели:** регистрация и вход по телефону (WhatsApp, Telegram),
   оформление заказа.
7. **Оплата:** Halyk ePay, Freedom Pay, Kaspi Pay (полуручной режим).
8. **Чеки:** Webkassa.
9. **Доставка:** ручные способы, СДЭК, Казпочта, Exline.
10. **Свои домены** с автоматическим TLS; вторая тема.
11. **Тарифы и биллинг платформы.**
12. **Гибридные приложения** магазинов (после решения open-questions №20).
13. **Выход в РФ:** ЮKassa, Т-Касса, АТОЛ Онлайн, Яндекс Доставка, Почта России —
    отдельная инсталляция.

## Открытые вопросы

Перед реализацией области сверься с `references/open-questions.md`. Если вопрос
там не закрыт, задай его пользователю, а не выбирай молча. Особенно важны:
- сервисный токен WB для юрлица РК;
- чей аккаунт разработчика для приложений;
- Kaspi: почтовый домен для служебных сотрудников, их минимальные роли,
  источник описаний товаров;
- канал OTP по умолчанию и запасной канал.
