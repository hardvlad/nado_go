# Языки и валюты

## Языки: ru, kk, en

**Строки интерфейса** (кнопки, заголовки, письма):
- каталоги переводов `internal/i18n/locales/{ru,kk,en}.toml` встраиваются через
  `embed`;
- библиотека — `github.com/nicksnyder/go-i18n/v2` (множественные формы
  по CLDR, в том числе для казахского);
- в шаблоне: `{{ T "cart.items" (dict "Count" .N) }}`;
- ключи точечные, по разделам: `cart.*`, `checkout.*`, `product.*`;
- ru — источник истины: новый ключ сначала добавляется в ru.toml;
- тест проверяет, что во всех каталогах одинаковый набор ключей.

**Контент** (товары, категории, страницы):
- хранится в `*_translations (entity_id, lang, ...)`;
- импорт с маркетплейсов даёт ru. Для kk и en перевод делается вручную в
  кабинете. Автоперевод — возможная платная функция, не MVP;
- если перевода нет, показывается язык магазина по умолчанию, и в `<head>`
  страницы нет hreflang на отсутствующий язык.

**Язык в URL:**
- `/` — язык по умолчанию, `/kk/...`, `/en/...` — остальные;
- middleware `ResolveLang` проверяет, что язык включён в магазине, иначе 404;
- формат дат, чисел и валют — `golang.org/x/text/language` + `message`, либо свой
  форматтер в `money` (пробел-разделитель тысяч, «₸» после числа, «₽» после числа).

## Валюты

| Понятие | Где | Пример |
|---|---|---|
| Базовая валюта магазина | `stores.base_currency` | KZT |
| Валюта отображения | cookie, из `store_currencies` | RUB |
| Валюта списания | определяется провайдером оплаты | KZT для Halyk, RUB для ЮKassa |

- Цены хранятся **только** в базовой валюте (`store_offers.price_minor`).
- Отображение: `display = convert(base, rate(base→display) × (1 + markup_bp/10000))`,
  округление half-up до минорной единицы. Витрина может дополнительно округлять
  до «красивых» цен — это настройка магазина, по умолчанию выключена.
- Курсы:
  - задача `fx.update` раз в сутки:
    - ЦБ РФ — `https://www.cbr.ru/scripts/XML_daily.asp`, XML в windows-1251,
      поле `VunitRate` или `Value/Nominal`;
    - НБРК — `https://nationalbank.kz/rss/rates_all.xml` ⚠️ формат проверить при
      реализации;
  - кросс-курсы считаются через базовую валюту источника и хранятся в `fx_rates`
    с датой;
  - нет свежего курса старше 3 дней — витрина показывает только базовую валюту и
    пишет предупреждение в лог. Со старым курсом не продаём.

## Оформление заказа при разных валютах

Пример: магазин в KZT, покупатель смотрит в RUB, а оплата идёт через Halyk
(KZT). Тогда:
1. Корзина показывается в RUB с пометкой «≈, оплата в тенге».
2. На шаге оплаты крупно показывается итог в KZT, который и будет списан.
3. Заказ сохраняет `display_currency=RUB`, `charge_currency=KZT`, `fx_rate`,
   суммы в валюте списания (основные) и в валюте отображения (справочно).
4. Чек (АТОЛ или Webkassa) формируется в валюте списания и по законодательству
   страны кассы. Чек 54-ФЗ в рублях, поэтому для РФ-кассы валюта списания должна
   быть RUB.

Если у магазина несколько провайдеров с разными валютами, покупатель видит в
способах оплаты валюту и сумму каждого.
