# Чеки

Старт в Казахстане (D-13): первым реализуется **Webkassa**, АТОЛ Онлайн — при
выходе в РФ.

Решение D-08 (nado-platform): чеки пробиваются через **отдельную** облачную кассу,
которую подключает продавец. Данные чека провайдеру оплаты не передаются, даже
если он умеет чеки. Правила 54-ФЗ и налогового кодекса КЗ — в
`references/receipt-rules.md`. **Прочитай этот файл перед изменением логики
чеков**: ошибка здесь означает штраф продавца от 75% суммы расчёта.

## Интерфейс и модель

```go
package fiscal

type Provider interface {
    Code() string
    Country() string // "RU" | "KZ"
    Sell(ctx context.Context, creds Credentials, r Receipt) (*Result, error)
    Refund(ctx context.Context, creds Credentials, r Receipt) (*Result, error)
    Status(ctx context.Context, creds Credentials, externalID string) (*Result, error)
}

type Receipt struct {
    ExternalKey   string          // наш уникальный ключ — идемпотентность на стороне кассы
    Kind          Kind            // Prepayment | FullPayment | Refund | RefundPrepayment
    Customer      Contact         // email или телефон — обязателен
    Company       Company         // ИНН/БИН, система налогообложения, адрес сайта (место расчётов)
    Items         []Item
    Payments      []PaymentPart   // электронно / зачёт предоплаты
    Total         money.Money
}

type Item struct {
    Name         string        // ≤ 128 символов
    Price        money.Money
    Quantity     decimal.Decimal
    Sum          money.Money
    VAT          VATRate       // наши коды ставок; соответствие кодам кассы — в адаптере.
                               // Подтверждены у АТОЛ: none, vat0, vat10, vat22, vat110, vat122;
                               // коды 5%/7% для УСН не подтверждены (см. receipt-rules.md, atol-online.md)
    Subject      Subject       // commodity | service | ...  (доставка — service)
    Method       Method        // full_prepayment | full_payment | ...
    MarkingCode  string        // «Честный знак», если товар маркированный
    Unit         string        // мера количества (ФФД 1.2)
}

type Result struct {
    ExternalID string
    Status     Status  // pending | done | failed
    Fiscal     *FiscalData // ФН, ФД, ФПД, дата, URL чека в ОФД — показываем покупателю
    Error      string
}
```

## Когда пробивать

| Событие заказа | РФ, `two_step` (по умолчанию) | РФ, `single` | КЗ |
|---|---|---|---|
| Оплата прошла (`paid`) | Предоплата 100% | Полный расчёт | Чек продажи |
| Передан покупателю (`delivered` или вручение в ПВЗ/курьером) | Полный расчёт с зачётом предоплаты | — | — |
| Возврат денег | Возврат прихода (с признаком того чека, что был последним) | Возврат прихода | Чек возврата |

- Схема `two_step` соответствует позиции ФНС для оплаты онлайн с доставкой позже.
  `single` — настройка на ответственность продавца, для товара, выданного в день
  оплаты. Выбор хранится в `store_fiscal_settings.receipt_scheme`.
- **Доставка** идёт отдельной позицией с признаком «услуга» и ставкой НДС
  продавца.
- **Скидки** распределяются по позициям до копейки, чтобы `Σ Sum = Total`.
  Округление остатка добавляется к самой дорогой позиции. Это частая причина
  отказов кассы.

## Надёжность

- Чек создаётся как строка `receipts` (`pending`) **в той же транзакции**, что и
  переход заказа, затем ставится задача `fiscal.sell` / `fiscal.refund`.
- Касса принимает чек асинхронно. Результат приходит через callback (если есть)
  или через опрос `Status` задачей с backoff.
- `ExternalKey` = `receipt:<id>`. Повтор отправки с тем же ключом у кассы не
  создаёт второй чек. Уточни механизм в reference: у АТОЛ это `external_id`.
- Ошибка валидации (неверная ставка, нет ИНН) — постоянная ошибка: чек
  `failed`, продавец видит в кабинете, что исправить, и кнопку «Пробить заново».
- Нельзя, чтобы чек молча не пробился. Дашборд кабинета показывает заказы с
  `paid`, но без `done`-чека старше часа.

## Настройки магазина

`store_fiscal_settings`:
- провайдер и учётные данные;
- система налогообложения (ОСН, УСН доходы, УСН доходы−расходы, ЕСХН, ПСН; в КЗ —
  свои режимы);
- ставка НДС по умолчанию;
- ставка на доставку;
- ИНН/БИН;
- адрес места расчётов (URL магазина);
- схема чеков.

Ставку конкретного товара можно переопределить в карточке. Импорт с маркетплейса
ставку не знает, поэтому используется ставка по умолчанию.

## Маркировка

D-15: в первой версии маркированные товары **не ограничиваются**. Они
продаются как обычные, чек пробивается без кода маркировки, на checkout ничего
не блокируется.
- Модель к маркировке готова: `order_items.marking_codes` и
  `Item.MarkingCode` существуют, но пока не заполняются. Не удаляй их.
- Риск принят пользователем, отвечает продавец. Если продавец или пользователь
  поднимет тему маркировки или начнётся выход в РФ, напомни о D-15 и предложи
  сбор кодов при сборке заказа (`references/receipt-rules.md`).
