# АТОЛ Онлайн (РФ) — облачная касса, справочник для `fiscal.Provider`

Сведения собраны 25.09.2026. Основной источник — PDF «АТОЛ Онлайн. Описание протокола v5 (ФФД 1.2)»: https://atol.online/upload/iblock/b3f/t09j33z47j6rv3v1h81vyv7dyz5h4q9x/API_atol_online_v5.pdf

**Важно:** это издание PDF — до 2026 года, ставок НДС 22% в нём нет. Новые значения описаны в https://help.atol.online/article/26152. Пометка «⚠️ не проверено» означает, что факт нужно сверить.

## Модель

- Касса, ФН и договор с ОФД оформлены **на продавца** (его ИНН). Регистрирует всё сам продавец в ЛК https://online.atol.ru/lk/.
- Платформа только передаёт данные чека по API от имени продавца.
- Продавец вводит в нашем кабинете данные из «файла настроек интеграции» в ЛК АТОЛ:
  - `login`;
  - `pass`;
  - `group_code`.
- Там же он указывает:
  - ИНН;
  - систему налогообложения (`sno`);
  - email организации;
  - адрес расчётов (`payment_address`) — URL его магазина на нашей платформе.
- `Credentials`: `{Login, Pass, GroupCode, INN, SNO, CompanyEmail, PaymentAddress}`. Логин и пароль хранятся зашифрованными.

## Авторизация

- `POST .../v5/getToken` с телом `{"login": "...", "pass": "..."}`. Ответ содержит `token` и `timestamp`.
- **Токен живёт 24 часа.** Новый запрашивайте **только** при ошибке `ExpiredToken` (код 11, HTTP 401). Кешируйте токен по подключению (в памяти или БД) и обновляйте лениво.
- Токен передаётся в заголовке `Token: <token>`; второй вариант — `?token=` в query.
- Если `getToken` вернул ошибку 21 («Код группы не поддерживает данную версию протокола»), у магазина ФФД 1.05. Нужен API v4 или перевод магазина на ФФД 1.2. Показывайте продавцу понятную ошибку.

## Регистрация чека

`POST .../v5/<group_code>/<operation>`, заголовки `Content-type: application/json; charset=utf-8` и `Token`.

| operation | Когда |
|---|---|
| `sell` | чек «Приход»: оплата (предоплата 100%) и закрывающий чек (полный расчёт) |
| `sell_refund` | «Возврат прихода» |
| `sell_correction`, `sell_refund_correction` | исправление ошибок (редко, вручную) |

Тело (минимум для интернет-магазина):

```json
{
  "timestamp": "25.09.2026 14:05:31",
  "external_id": "rcpt_01J8...",
  "service": {"callback_url": "https://<наш-домен>/webhooks/fiscal/atol/<connectionID>"},
  "receipt": {
    "client": {"email": "buyer@example.com", "phone": "+79990001122"},
    "company": {"email": "shop@example.com", "sno": "usn_income", "inn": "5010051677", "payment_address": "https://shop.example"},
    "items": [{
      "name": "Футболка синяя XL",
      "price": 1250.00, "quantity": 1.0, "measure": 0, "sum": 1250.00,
      "payment_method": "full_prepayment",
      "payment_object": 1,
      "vat": {"type": "vat122", "sum": 225.41}
    }],
    "payments": [{"type": 1, "sum": 1250.00}],
    "total": 1250.00
  }
}
```

- `timestamp` — формат `dd.mm.yyyy HH:MM:SS`. Часовой пояс в документе не указан ⚠️ не проверено; используйте время Москвы или время магазина единообразно.
- `external_id` — наш ID документа. Он **уникален в пределах `group_code`**. Повтор с тем же `external_id` возвращает ошибку `IncomingExternalIdAlreadyExists` (код 33). Это и есть идемпотентность:
  - генерируйте ID один раз на документ и сохраняйте в БД до отправки;
  - на ошибку 33 отвечайте получением статуса, а не новым чеком.
- `client`: **обязателен `email` или `phone`**.
  - Телефон — в формате `+7...` без пробелов.
  - Если указаны оба поля, ОФД отправит чек только на email.
- `company.sno`:
  - `osn`;
  - `usn_income`;
  - `usn_income_outcome`;
  - `esn`;
  - `patent`;
  - `envd` — отменён, не использовать.
- Суммы — **числа в рублях** с копейками: целая часть до 8 знаков, дробная до 2. **`sum` позиции должна равняться `price × quantity`**.
  - Скидку распределяйте в цену позиции, а не отдельной строкой.
  - Из `money.Money{Minor}` конвертируйте аккуратно; JSON-число формируйте из строки `%d.%02d` (например, `json.Number`), без float-арифметики.
- `measure`: `0` — штуки/единицы; `11` — кг; `41` — литр; и т.д. Для товаров почти всегда `0`.
- `payment_method` (тег 1214):
  - `full_prepayment` — предоплата 100%;
  - `prepayment`;
  - `advance`;
  - `full_payment` — полный расчёт;
  - `partial_payment`;
  - `credit`;
  - `credit_payment`.
- `payment_object` (тег 1212, **числом** в v5):
  - `1` — товар;
  - `2` — подакцизный товар;
  - `4` — услуга (например, доставка);
  - `10` — аванс/предоплата (когда предмет расчёта неизвестен);
  - `33` — маркированный товар **с кодом**;
  - `32` — маркированный товар без кода;
  - `31` / `30` — подакцизный маркированный с кодом / без кода.
- `vat.type`:
  - `none`, `vat0`, `vat10`, `vat110`;
  - `vat22`, `vat122` — с 2026 года;
  - `vat20`, `vat120` — для расчётов до 2026 года.
  - Ставки УСН 5% и 7% — `vat5`, `vat7`, `vat105`, `vat107` ⚠️ не проверено: в PDF этого издания их нет, сверьте с актуальной схемой https://online.atol.ru/possystem/v5/schema/sell.
  - `vat.sum` можно не передавать: касса посчитает сама.
- `payments[].type`:
  - `0` — наличные;
  - `1` — безналичные;
  - `2` — зачёт предоплаты (в закрывающем чеке);
  - `3` — кредит;
  - `4` — встречное предоставление.
- Маркировка — в позиции с `payment_object: 33`:
  - `"mark_processing_mode": "0"`;
  - `"mark_code": {"gs1m": "<base64 кода DataMatrix>"}` — либо другой тип кода из объекта `mark_code`.
- Актуальная JSON-схема: https://online.atol.ru/possystem/v5/schema/sell. Валидируйте тела запросов в тестах.

Ответ: `{"uuid": "...", "status": "wait", "error": null, "timestamp": "..."}`. `uuid` сохраните как `ExternalID`.

## Результат

- Через **callback**: если передан `callback_url`, АТОЛ отправит POST с результатом, тело как у `report`. URL должен соответствовать маске АТОЛ, иначе будет ошибка «callback_url не соответствует маске».
  - Подписи у callback нет ⚠️ не проверено. **Всегда перезапрашивайте `report`** по `uuid`.
- Через **опрос**: `GET .../v5/<group_code>/report/<uuid>` с заголовком `Token`.
  - Если callback не пришёл за разумное время (в документе упоминаются 300 секунд), опрашивайте с backoff.
- Статусы:
  - `wait` — в обработке;
  - `done` — зарегистрирован;
  - `fail` — ошибка.
  - При `done` в `payload` приходят фискальные данные: номер ФД, ФП, ссылка ОФД и т.д.

Маппинг на наш `FiscalReceipt.status`:
- `wait` → `pending`;
- `done` → `registered`;
- `fail` → `failed`. Показать продавцу, дать повтор с **новым** `external_id` после исправления данных.

## Подвохи

- Токен 24 ч. Не запрашивайте его на каждый чек: у АТОЛ ограничено число одновременно действующих токенов.
- `price × quantity` должно **точно** совпадать с `sum`, а `sum` всех позиций — с `total` и суммой `payments`. Иначе будет ошибка валидации.
- Для предоплаты — расчётные ставки (`vat122`, `vat110`); для закрывающего чека — обычные (`vat22`, `vat10`). Подробнее в `receipt-rules.md`.
- Ошибка 33 (дубль `external_id`) — это не сбой: запросите статус существующего документа.
