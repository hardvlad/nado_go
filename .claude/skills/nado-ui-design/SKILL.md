# Оформление страниц nado

Решение **D-21** (nado-platform → decisions.md): **у каждой страницы
платформы есть светлый и тёмный вариант**. Это касается:
- лендинга `nado.kz`;
- кабинета продавца `app.nado.kz`;
- витрин магазинов (все темы, D-16);
- страниц ошибок;
- экранов гибридных приложений.

Экран, свёрстанный только в одном режиме, не готов, даже если он «пока
внутренний».

Режимов три:

| Режим | Поведение |
|---|---|
| `system` (по умолчанию) | следует `prefers-color-scheme` устройства |
| `light` | всегда светлый |
| `dark` | всегда тёмный |

- Переключатель есть на каждой странице: в шапке кабинета и на витрине, в
  мобильном меню. Выбор запоминается.
- Продавец выбирает режим **по умолчанию** для своего магазина
  (`stores.theme_settings.default_mode`). Отключить переключатель для покупателей
  нельзя.

## Токены вместо цветов

Компоненты используют **только семантические CSS-переменные**. Цвет в правиле
компонента (`#fdf1f1`, `rgb(...)`, `white`) — ошибка: в тёмном режиме такой
элемент останется светлым пятном.

```css
/* web/static/css/tokens.css — общий для кабинета и лендинга; у тем витрины свой такой же набор */
:root {
  color-scheme: light;
  --color-bg:            #f6f7f9;  /* фон страницы */
  --color-surface:       #ffffff;  /* карточки, шапка, модалки */
  --color-surface-2:     #f0f2f5;  /* вложенные блоки, заголовки таблиц */
  --color-text:          #1b1f24;
  --color-text-muted:    #5c6673;
  --color-border:        #e2e5ea;
  --color-primary:       #2563d9;  /* бренд: кнопки, ссылки */
  --color-on-primary:    #ffffff;  /* текст на primary */
  --color-success:       #1d7a45;  --color-success-bg: #e6f5ec;
  --color-warning:       #8a5a00;  --color-warning-bg: #fff4d6;
  --color-danger:        #b02a2a;  --color-danger-bg:  #fdeaea;
  --color-info:          #1f5fbf;  --color-info-bg:    #e8f0fd;
  --color-media-bg:      #ffffff;  /* подложка фото товаров */
  --color-focus:         #2563d9;
  --shadow-1: 0 1px 2px rgb(16 24 40 / .06), 0 1px 3px rgb(16 24 40 / .10);
}

/* Тёмные значения задаются дважды: для явного выбора и для «как в системе». */
:root[data-theme="dark"] { /* ...тёмные значения... */ }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { /* ...те же тёмные значения... */ }
}
```

- Имена токенов одинаковые во всех темах. Темы витрины переопределяют значения,
  а не набор. Полный список токенов — в `references/tokens.md`.
- Чтобы тёмные значения не расходились в двух блоках, храни их один раз в
  исходнике и собирай CSS при сборке (`go generate`). Либо используй
  `light-dark()` (`color: light-dark(#1b1f24, #e6e8eb)`) при `color-scheme: light
  dark` — поддержка браузеров: ⚠️ проверить на целевых устройствах, особенно в
  WebView старых Android.

## Правила тёмной темы

Тёмная тема — это не инверсия светлой:
- **Фон** не чисто чёрный: `#0f1115`–`#16181d`. **Текст** не чисто белый:
  `#e6e8eb`, второстепенный — `#9aa4b2`. Чистые `#000`/`#fff` режут глаза и
  «размазываются» на OLED.
- **Глубина** передаётся светлее поверхностью (`surface` светлее `bg`, `surface-2`
  ещё светлее), а не тенями: тени на тёмном почти не видны.
- **Цвета бренда и статусов** в тёмной теме светлее и менее насыщены, иначе
  синий и красный «вибрируют» на тёмном фоне. Фоны статусов (`*-bg`) —
  приглушённые тёмные оттенки, а не пастель светлой темы.
- **Границы** в тёмной теме заметнее, чем кажется нужным: `#2a2f37`–`#343a44`.
- `color-scheme: dark` в тёмном блоке. Тогда нативные поля, скроллбары,
  `<select>` и календарь тоже тёмные.

## Контрастность — в обоих режимах

WCAG 2.2 AA:
- обычный текст — не меньше 4.5:1;
- крупный (от 24 px или от 18.66 px жирный) — 3:1;
- границы полей, иконки-кнопки, фокус — 3:1.

Проверяется каждая пара «текст/фон» из токенов **в обоих режимах**, тестом
(см. ниже). Типичные ошибки: `text-muted` на `surface-2`, белый текст на светлом
`primary` продавца, `warning` на `warning-bg`.

## Цвета бренда продавца (витрина)

- Продавец задаёт в настройках темы основной цвет. Тёмный вариант **платформа
  вычисляет сама**: в OKLCH поднимает светлоту до ~0.72–0.80 и снижает
  насыщенность, затем проверяет контраст с `bg` и `on-primary`. Продавец может
  задать тёмный вариант вручную.
- Цвет, не проходящий контраст хотя бы в одном режиме, не сохраняется. Кабинет
  показывает превью обеих тем и предлагает ближайший подходящий оттенок.
- Вычисление — в Go (`internal/ui/color`: sRGB ↔ OKLCH, контраст по WCAG),
  покрыто табличными тестами.

## Логотипы, фото, иконки

- **Логотип:** в настройках магазина два файла, `logo_light` и `logo_dark`. Если
  тёмного нет, светлый выводится на подложке `--color-media-bg` со скруглением,
  а не прямо на тёмном фоне.
- **Фото товаров** почти всегда на белом фоне. В тёмной теме они стоят в карточке
  с `background: var(--color-media-bg)` и скруглением, чтобы белые прямоугольники
  выглядели как намеренные плитки. Фильтры на фото (`invert`, `brightness`)
  запрещены: они искажают товар.
- **Иконки** — inline SVG или спрайт с `fill="currentColor"` /
  `stroke="currentColor"`. PNG-иконки не используются.
- **Описания товаров с маркетплейсов** (HTML после санитайзера) могут содержать
  inline-цвета. Санитайзер вырезает `color`, `background` и `style`, иначе
  чёрный текст исчезнет на тёмном фоне.
- **Графики в кабинете:** палитра из токенов (`--chart-1…6`) с отдельными
  значениями для тёмной темы. Библиотека графиков берёт цвета из
  `getComputedStyle` и перерисовывается при смене темы.

## Переключение без мигания (SSR)

- Выбор хранится в cookie `nado_theme=system|light|dark`: на домене магазина
  для витрины, на `app.nado.kz` для кабинета. Для вошедших дублируется в профиль
  (`users.ui_theme`, `customers.ui_theme`), чтобы переживать смену устройства.
- Сервер рендерит `<html data-theme="light|dark">` из cookie, а для `system`
  атрибут не ставит. Мигания нет: первая отрисовка уже правильная, и для
  `system` работает media-запрос без JS.
- `<head>` каждой страницы:
  ```html
  <meta name="color-scheme" content="light dark">
  <meta name="theme-color" content="#f6f7f9" media="(prefers-color-scheme: light)">
  <meta name="theme-color" content="#0f1115" media="(prefers-color-scheme: dark)">
  ```
  При явном выборе режима сервер выводит один `theme-color` нужного цвета: это
  цвет строки состояния на телефоне и в PWA.
- Переключатель — `<button>` с текстом для скринридера («Тема: как в системе»).
  Логика — в статическом `web/static/js/theme.js` (CSP `script-src 'self'`, без
  inline): меняет `data-theme`, `theme-color` и cookie (`SameSite=Lax; Max-Age`
  на год) и шлёт событие `nado:theme-changed` (для графиков). Сохранение в
  профиль — отдельный `fetch`/`hx-post`, страница не перезагружается.
- Смена темы идёт без анимации всех цветов (`transition` на `*` запрещён). Всё
  остальное учитывает `prefers-reduced-motion`.

## CSP и настройки темы магазина

CSP скелета: `style-src 'self'`, inline-стили запрещены. Поэтому переменные
темы магазина (цвета продавца для обоих режимов, шрифт) отдаются **отдельным
файлом**: `GET /_theme/vars.css?v={хеш настроек}` генерирует CSS из
`stores.theme_settings`. Файл кешируется надолго, при изменении настроек меняется
хеш. Атрибут `style="..."` в шаблонах тоже не используется: только классы.

## htmx

Фрагменты, которые подменяет htmx, наследуют токены, и дополнительной работы не
требуют — если в них нет захардкоженных цветов. Индикаторы загрузки и тосты
тоже на токенах (`htmx.config.includeIndicatorStyles = false`, свои стили).

## Гибридные приложения

WebView наследует `prefers-color-scheme` системы. Нативная оболочка
синхронизирует с режимом страницы:
- цвет строки состояния и навигации (Capacitor StatusBar);
- splash screen (две версии);
- иконку уведомлений.

Подробнее — nado-storefront → `references/themes-and-apps.md`.

## Письма

HTML-письма (заказы, коды) делаются светлыми: поддержка тёмного режима в
почтовых клиентах непредсказуема. Письма содержат `<meta name="color-scheme"
content="light only">`, а логотип лежит на белой подложке, чтобы клиенты с
принудительной инверсией не испортили его.

## Проверка готовности экрана

- [ ] Нет цветов вне файлов токенов. Тест `TestNoRawColors` ищет
      `#[0-9a-f]{3,8}\b|rgb\(|hsl\(` в `web/**/*.css` и `*.gohtml`; исключения —
      только файлы токенов.
- [ ] Каждая тема определяет **все** токены в светлом и тёмном блоках. Тест
      разбирает CSS темы и сравнивает множества имён; загрузчик тем отказывается
      запускать тему без полного набора. Это ловит ошибку при старте, как
      `Warmup` шаблонов.
- [ ] Контраст пар из `references/tokens.md` проходит AA в обоих режимах (тест на
      `internal/ui/color`).
- [ ] Экран просмотрен в светлом, тёмном и системном режиме на 360 px и
      1280 px. Проверены фокус, ошибки форм, пустые состояния, модалки, тосты.
- [ ] Логотип, фото и графики выглядят нормально в тёмном режиме.

## Миграция скелета

В текущем `web/static/css/app.css` часть цветов задана прямо в правилах
(`.alert--error`, `.badge--*`, `.table th`). При первой же задаче по вёрстке
кабинета вынеси их в токены по этой схеме и добавь тёмный блок. Не делай это
молча в чужой задаче: скажи пользователю.
